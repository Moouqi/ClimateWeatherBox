# 气候与四季

适配 WorldBox 0.50.x + NeoModLoader。

## 功能

- 每个地块保存 `日照 / 温度 / 湿度 / 风向 / 风速` 连续值。日照和温度由当前太阳直射经纬度与标准太阳高度角动态驱动；陆地升降温较快，海洋具有更强热惯性。
- 湿度与温度、地表类型耦合：温度上升会提高饱和水汽上限，因而陆地和海洋的当前相对湿度都会降低；暖海蒸发会另外补充水汽。海洋和沿岸供给水汽，枫林/白桦林/雨林/沼泽保湿，沙漠和高温裸地快速失水。
- 河流使用原版 `shallow_waters` 浅滩主地块模拟：系统从相互分离的山巅水源出发，读取平滑后的地形等高面，优先沿最大坡降方向垂直穿越等高线；缓坡上允许曲流，封闭洼地才借助水体距离场短暂爬升，最终接入最近的有效海洋或湖泊。单个浅滩水坑、狭长残留水带不会被误判为湖泊。山巅本体保留，河道从相邻格开始，并只写入单格宽、严格四邻接的中心线；支流只能汇入已验证的中心线。河网规划会避开建筑、城区和岩浆，每 5 秒最多写入 128 格，并按“河口→上游”顺序生成；水源数随地图面积缩放且不超过 24 条。河流与浅滩会持续湿润半径 4 格内的陆地，湿度增益随距离衰减。
- 普通自然群系必须连续满足同一个目标群系约 45 秒才会被气候系统替换，短时昼夜或降雨波动会重置候选计时。原版自然扩张或玩家放置的普通群系在通过加宽适生检查后会被记录并保留，只要当地仍处于该群系耐受区就不会被核心选择立即改回；越出耐受区后再恢复气候转换。模组自身的写入不会被误记为外部扩张。
- 春、夏、秋、冬自动轮转；默认每季 180 秒。
- 高湿生成雨云；温度越高，对流越强、降雨云出现概率与单次数量越多，暖海会进一步加成。湿热区生成雷电；暖海/沿岸的飓风概率会随温度单调增大（使用原版龙卷风单位）。
- 雨云生成使用当地季节系数：北半球和南半球各自在本地夏季提高降雨概率，冬季降低；热带辐合雨带跟随太阳直射纬度南北移动，直射带附近进入雨季并额外增加单次生成的雨云数量，赤道附近在春分、秋分前后形成双雨季。季节倍率约为 0.55–1.75，仍需当地湿度达到基础成云条件。
- 本模组生成的雨云在移动期间每 1.5 秒按当前落点结算降水：海洋中心格补充约 4% 湿度、相邻格约 1.8%；落到陆地时使用 1.8 倍土壤补湿，中心格约 7.2%、相邻格约 3.2%，上限均为 98%。生成云时消耗的水汽会随风输送并在实际降雨路径重新补给地面。
- 普通自然群系按现实气候带重新校准：热带群系核心温度从 18°C 起算，干旱、草原、枫林、白桦林、丛林和沼泽采用分级温湿度区间；当前版本不存在森林群系资产，原森林气候位中不满足枫林或白桦林条件的区域由草原补空。由于游戏保存的是瞬时相对湿度而不是年降水量，判定使用加宽的适生滞后区间，避免短时天气造成群系频繁跳变。
- 左上角面板显示季节、全图平均温度、仅陆地平均湿度和天气计数；海洋不参与平均湿度统计，F8 显示/隐藏。
- 默认全球模板的水平中线是赤道，上下边界是南北两极；自定义纬度范围后，地图各行按设定的南界到北界线性映射，赤道可以位于任意行或完全处于地图之外。
- 采用现实纬度气候近似：太阳直射点在南北回归线间移动；赤道湿润、副热带干旱、中纬度较湿、极地寒冷干燥，南北半球关于赤道镜像且季节相反。
- 群系生成和原版自然扩张同时受纬度约束：雨林核心限制在南北纬 30° 内，稀树草原约 40° 内，沼泽约 60° 内；枫林主要位于约 18°–55° 的暖温带，白桦林主要位于约 35°–70° 的冷温带和亚寒带。冻土通常从约 55° 高纬开始，低纬只有峰顶可形成高山冻土；沙漠不设纬度硬限制。扩张耐受纬带比核心范围略宽，避免边界闪烁。
- 面板可选择全球、北半球或南半球模板作为经纬范围快捷预设，也可分别滑动设置纬度南/北界（−90°～90°）和经度西/东界（−180°～180°）。坐标范围会保存，并统一驱动太阳高度、昼夜、温湿度、气压风场、雨带、季节和群系纬度限制；只有释放滑杆后才提交设置，完整气候重算再按每帧最多 2048 格拆成温湿度/气压和风场两个阶段，避免大地图拖动卡顿。
- F8 面板温标右侧提供“生成河流”按钮，可按点击时的最新山地、水体和城市分布手动补充河网。已有河道不会被删除或重铺；生成队列执行期间按钮会显示剩余浅滩格数并暂时禁用，完成后可以再次点击寻找其他尚未使用的山巅水源。
- F4 切换地形等高线图层：系统按深海、近海、浅滩、沙地、低地、高地、丘陵、山地和山巅生成相对高度，再使用 3×3 加权平滑形成连续等高面和 12 级等高带；蓝色表示水深、绿色表示低地、褐色表示高地、白色表示峰顶，深色线为等高线。F5 切换气压与风向图层（蓝色低压、红色高压、深色线为 4 hPa 等压线；风箭头按屏幕尺寸自适应密度，对 3×3 局地风场平滑，长度与亮度表示风速，并使用深色描边保证在海陆上均清晰可见），F6 切换温度图层（蓝→绿→红），F7 切换湿度图层（橙→蓝）；再次按键关闭图层。温度界面按当前自定义范围显示 30° 间隔经纬网、60° 间隔经度标签、纬度标签与赤道线。
- 风场由动态海平面气压梯度主导，并叠加现实三圈环流、南北半球相反的科里奥利偏转和地形绕流；北、南半球分别在 0°–30°形成向西且趋向赤道的东北/东南信风，30°–60°形成向东且趋向高纬的西风，60°–90°形成向西且趋向副极地低压的极地东风。赤道低压带随太阳直射点移动，副热带高压和副极地低压随季节小幅摆动；夏季大陆形成热低压、冬季大陆形成冷高压，海洋以更慢速度产生反相季风压差，极地高压冬强夏弱。移动的天气尺度扰动、温度异常、湿度和云量继续塑造局地高低压。30°和60°附近采用平滑过渡，风箭头始终保留由高压指向低压的分量。F5 会额外标出平均气压带；低压与局地辐合区会加速水汽凝结、延缓云层消散并汇聚顺风云量，高压下沉区则抑制成云、加速破云。
- 地形变化会主动使气候缓存失效：海陆、沙地、山地、山峰、雪峰、群系、道路、海冰以及原版冻融发生实际改变后，系统读取 setter 完成后的最终地形，同步重算中心及邻格温度/湿度，并刷新受温差和地形高度梯度影响的外圈风场。大规模地形修改按每帧最多 1024 个中心去重批处理，避免重复 setter 引发卡顿。
- 原版云的固定向右位移已被局地风二维位移替代：云每帧按实时画面坐标反查所在地块，跨越不同风带时会随当地风向转向；本模组雨云会被明确跟踪并以略高于普通云的稳定系数顺风漂移。原版龙卷风的移动目标偏向下风侧；船只保留原版航线与水路寻路，顺风最高提速 42%，逆风最低降至 58%，不会被风推上陆地。
- 降雨云会检查下风三格内的山峰：遇峰时降速并向左右较低的一侧绕行，雪峰的阻挡与减速效果更强；绕流后仍沿新的局地下风方向继续移动。
- 云层记录本轮生命周期是否已经进入地图：从地图外生成、尚未入图的原版云仍暂用原版向右移动；一旦入图，越过上下左右任一实际地图边界便立即按原版流程渐隐回收，防止逆风时在左侧边界反复弹回堆积。对象池复用云时会自动清除上一轮的入图状态。
- 普通云、雨云、雷云、雪云、酸雨云、火云等全部 `Cloud` 类型共享防卡死监控：在游戏未暂停时连续约 10 秒几乎没有位移会渐隐回收；无原版寿命且因闭合环流长期不出图的云，会依据地图宽度和自身速度在约 120–360 秒达到驻留上限。判定阈值低于正常山峰绕流速度，不会清除仍在缓慢移动的云。
- 图层开启时，将鼠标悬停在任意地块可查看该格的温度、湿度、日照、风向风速、半球/纬度带和坐标。
- 温度图层显示当前太阳直射点、直射纬度和移动日照经度；单半球模板会提示直射点是否位于模板之外。
- 日照与温度每 0.5 秒分批演化，完成一轮后才上传温度纹理。温度由纬度/季节日平均值与有限昼夜扰动组成：沙漠昼夜振幅最大，枫林、白桦林和湿地较小，海洋仅有约 0.5–2.5°C 的目标振幅；湿度和沿海环境会进一步缓和温差。温度使用基于实际模拟时间的指数热惯性，不再随帧率、地图大小或刷新批次改变响应速度。
- 面板提供 0%–200% 温室气体滑杆并自动保存。100% 代表类地自然温室效应（约 +33°C）；0% 接近无温室大气，高浓度则逐步推高平衡温度。调节后会按陆地/海洋热惯性逐渐变温，不会瞬间跳变。
- 面板提供独立的 0%–200% 大气厚度滑杆并自动保存。100% 保持类地太阳透射；较薄大气让更多可见光与短波热量到达地表，较厚大气会同时降低地块日照数值、地图白昼亮度、日平均太阳加热和白昼温度扰动。该参数不重复计算温室气体的长波保温效果，面板会实时显示当前光/热透射百分比。
- 山峰和山地按海拔应用温度递减，峰顶最高约额外降低 12°C；雪峰因高反照率减少约 28% 的太阳吸收，并额外降温约 4°C。
- 冻结陆地、积雪地表和三类冻结海面具有强冰雪反照率：入射日照数值仍正常显示，但白昼只吸收约 38% 的太阳热量；冰雪升温热响应约为普通地块的 55%，降温也因热惯性略微减慢。反照率负责主要冷却反馈，避免旧版“夜间快速降温、白天几乎无法升温”人为放大昼夜差。
- 岩浆保留原版 `lava0`–`lava3` 地块、`mat_world_object_lit` 发光材质、伤害和世界法则；自转夜幕会为原版岩浆材质保留透光，高等级岩浆更明亮，但不创建额外灯光。岩浆作为强局地热源参与温度、湿度和风场，并按 `lava3→lava2→lava1→lava0→丘陵` 逐级散热凝固；冷空气、夜晚、高湿及邻接海水会加速冷却，炎热干燥的白昼会减慢冷却。“永久岩浆”或“盖娅盟约”开启时不由气候系统凝固。
- 模拟地球自转：带柔和晨昏边缘的黑夜夜幕从地图左侧向右侧循环，并与直射点及温度日变化保持同一相位。
- 夜幕按太阳高度角逐纬度计算：夏半球高纬出现极昼，冬半球高纬出现极夜，极圈范围随季节移动。
- 深夜读取原版 `age_dark.era_effect_overlay_alpha`，并按原版 top/material 双夜色通道计算等效暗度 `1-(1-α)²`；默认 α=0.3 时深夜约 51%。
- 冰雪完全由局地温度场决定：浅滩约 −2°C、近海约 −6°C、深海约 −10°C 开始结冰；沙地约 −5°C、普通陆地约 −8°C 时交给原版冻结机制处理。回暖约 10°C 后解冻，滞后区间可避免闪烁。
- 三种海域分别使用独立的 top tile type：`frozen_shallow_sea`、`frozen_close_sea`、`frozen_deep_sea`。冻结时仅替换海洋顶层并保存原地形，融化时精确恢复原浅滩/近海/深海；不设置原版 `frozen` 标志，不允许陆地冰雪顶层覆盖海洋。
- 原版纪元解冻行为会被局地温度过滤：由本模组冻结且仍低于融化阈值的地块不会被原版下一帧立即融化；达到回暖阈值后恢复原版解冻。
- 温度可在面板切换摄氏（°C）或华氏（°F）并持久保存；内部 0–1 气候温度映射为 -50°C 至 50°C。
- 冻土群系核心适生线为约 −5°C，并优先于干旱沙漠判断；已有冻土可在约 2°C 以下保持，以形成稳定的过渡带。冬季低温区会随温度场向赤道推进，回暖后再恢复当地适生群系。
- 地块气候采用带交错边缘的赤道波前刷新：按自定义纬度到赤道的实际距离排序，从范围内最接近赤道的一侧向高纬推进；同纬度地块加入确定性微小错位，避免整行批量变化形成横向条带。每 5 秒集中判定最多 4096 格，所有地块都会完成适生性与持续时间检查；成熟的群系变化进入全图去重队列，再按每周期最多 192 格执行。预算耗尽只会延后写入，不再跳过或遗失后续地块。
- 区域黑夜的建筑与岩浆光晕由夜幕 shader 的 LightMask 承担：每 0.4 秒遍历具备 `draw_light_area` 的建筑和四档岩浆，在夜幕纹理上保留透光；普通纪元下原版 `light_areas` 光斑经合成后 alpha 恒为 0，整条每帧绘制链路被跳过，黑暗纪元仍走原版光照。
- 窗户光 sprite 直接渲染在 Objects 层：地图仍存在夜晚时保持原版光照管线开启，`DynamicSprites.getBuildingLight` 按建筑所在地昼夜过滤——白天的建筑不提交窗户光，夜侧建筑保持原版发光效果。
- 黑夜、温度、湿度和太阳直射点均裁剪在地图游戏视口内，不覆盖底部工具栏、统计栏和纪元操作界面。
- 检测到任意 `ScrollWindow` 弹窗后暂停绘制全部气候覆盖层与提示框，关闭弹窗时自动恢复。

模组只改普通自然群系，保留腐化、糖果、地狱等特殊群系。频率常量集中在 `ModClass.cs` 顶部，便于二次调整。

## 渲染架构

所有地图视觉（夜幕、数据图层、等压线、等高线、风尾迹、经纬网）由 `Source/Render/` 下的世界空间渲染体绘制：模拟状态写入 `ClimateFieldSet` 的字段纹理，挂在游戏 `MapOverlay` 排序层的两块面片和一个线条 Mesh 用自定义 shader 实时合成画面，一次合成、无需逐帧 GUI 重绘；接缝预览和回绕窗口的副相机自动拍到全部图层。晨昏线、等高带、等压线全部在 shader 内逐像素计算。文字类内容（图例、标签、悬停提示框与 F8 面板）保留 IMGUI。模块说明见 `Source/README.md`。

## GPU 大气与直写显示

大气模拟（风、气压、气温、水汽、云、降水与输运）完整运行在 compute shader 上（`.UnityProject/Assets/ClimateAtmosphere.compute`，与 CPU 实现逐条对应）。kernel 每模拟一秒把气压/风/水汽**直接写入** `AtmosDisplay` 渲染纹理，等压线图层采样该纹理，显示路径零 CPU 回读；异步回读只服务于群系、天气与云生成等玩法逻辑。任何无效数据（NaN、负质量）都会触发自动回退：丢弃 GPU 状态、恢复 CPU 模拟与 CPU 上传纹理，画面无缝切换。

shader 与材质打包在 `Gpu/climatelayers`（Unity 2022.3.60f1 AssetBundle）。资源缺失时模组正常模拟，只记录一条警告且不显示图层。重新构建：

```powershell
powershell -ExecutionPolicy Bypass -File build-shaders.ps1
# Unity 不在默认路径时： -UnityPath "<路径>\Unity.exe"
```

## 安装

将整个 `ClimateWeather` 文件夹复制到 WorldBox 的 `Mods` 目录。已编译 DLL 位于 `bin/ClimateWeather.dll`。

模组会等待地图地块全部生成后再初始化气候；新建世界的生成过程中短暂显示 0% 属正常现象。
